# CER 工作法

[English](README.en.md)

CER 工作法適合長期、多批、容易中斷，或結果很重要的 AI 工作。

它會把工作分清楚：一位主控先確認目標、限制和驗收方式；一位固定執行者負責實際寫檔；需要更小心時，再請獨立覆核者檢查風險。普通小任務可以繼續用普通單一對話，不一定要啟動 CER。


## 開始使用

安裝後，以明確帶 CER 的語句啟動：

```text
CER 啟動：<你想完成的事、限制、優先順序>
```

或：

```text
/CER-start <你想完成的事、限制、優先順序>
```

單獨 `開工` 不會啟動 CER；它保留給你目前的工作方式。

## 操作指令

| 指令 | 自然語言 | 用途 |
|---|---|---|
| `/CER-start <任務、限制、優先順序>` | `CER 啟動：...`／`CER 開始：...`／`CER 開工：...` | 啟動 CER 工作模式。 |
| `/CER-stop` | `停止 CER，改用普通單一對話繼續。` | 停用 CER，回到普通單一對話；這不代表任務已完成。 |
| `/CER-close` | `CER 收工。`／`CER 關閉。`／`關閉 CER。` | 正式收尾；整理成果、未完成事項和需要保留的狀態。 |
| `/CER-status` | `顯示 CER 狀態。` | 顯示目前進度、下一個停點和已知問題。 |
| `/CER-help` | `顯示 CER 指令。` | 顯示可用指令。 |

單獨 `收工` 不會觸發 CER close，也不會被當成 `/CER-stop`。

## CER 怎樣工作

1. 主控先確認任務要做到甚麼、哪些不做、需要讀哪些資料、甚麼情況要停下問你。
2. 確認清楚後，固定執行者負責實際修改。這樣長任務不會每批都換人寫檔。
3. 如果風險較高，或需要有人從另一個角度檢查，主控會請獨立覆核者看受影響的範圍。
4. 需要你決定方向、補資料、處理重大問題或驗收成果時，主控才回到你面前。
5. CER 不會自行建立固定專案文件，也不會把自己的流程紀錄當成你的正式文件。

CER 啟動時會先確認各個工作對話能互相回傳訊息；若未能確認，會停止並告知，不會假裝已開始。

## 和普通單一對話有甚麼分別

普通單一對話適合一次性小修改，或你想一步一步帶著 AI 做的工作。

CER 適合較長、分批、容易中斷，或需要更穩定交付的工作。它的重點不是多開幾個角色，而是讓同一位執行者負責寫檔，並在需要時加入獨立覆核。

CER 會多花一點啟動時間確認任務和回傳是否成立。這是為了避免工作做到一半才發現目標、責任或驗收方式不清楚。

## 停用和收尾有甚麼分別

`/CER-stop` 是停用 CER。用在你想中途改回普通單一對話時。它只表示不再用 CER 分工繼續，不代表任務已完成。

`/CER-close` 是正式收尾。用在任務已完成，或你要把目前成果、風險和未完成事項整理清楚時。收尾後，這一輪 CER 就只保留作歷史，不再接下一輪工作。
